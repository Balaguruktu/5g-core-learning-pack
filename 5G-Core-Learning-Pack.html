AMF — Access & Mobility Management Function

The AMF is the single control-plane contact for a UE in the 5G Core for access and mobility. It terminates NAS (N1) and NGAP (N2). It does not own the PDU session — that is SMF — but it always relays session NAS and coordinates N2 resource setup.

What the AMF is responsible for

Owns

  • Registration / deregistration / mobility registration update
  • Connection management (CM-IDLE ↔ CM-CONNECTED)
  • Reachability: Registration Area, paging, TAI list
  • NAS security context (after AUSF authentication)
  • UE context toward RAN (Initial Context Setup, handover signalling)
  • Selecting / discovering SMF, AUSF, UDM, PCF, NSSF (via NRF)

Does not own

  • IP address allocation (SMF / UPF)
  • PFCP rules on UPF (SMF on N4)
  • User-plane forwarding (UPF on N3/N6)
  • Long-term subscriber key (UDM / ARPF)
  • Final PCC decision (PCF) — AMF may get AM/UE policy only

AMF state machines (short)

RM — Registration

RM-DEREGISTERED → after Accept → RM-REGISTERED. Holds Registration Area (list of TAs) and 5G-GUTI.

CM — Connection

CM-IDLE: no N2 UE association; paging needed. CM-CONNECTED: NGAP UE context exists; NAS can flow anytime.

Security

After 5G-AKA + SMC, AMF holds KAMF-derived NAS keys. ngKSI identifies the context.

Core deep dive

Identity & security

TermMeaning
SUPI / SUCIPermanent id / concealed form on air

5G-AKAPrimary auth via AUSF; AMF runs NAS challenge exchange
KAMFKey used to derive NAS integrity/enc keys at AMF
ngKSIKey set identifier in NAS security

Session / QoS / UP

PDU session

UE↔DNN association. AMF selects SMF; SMF owns it.

QoS flow / 5QI

QFI inside the session. AMF only transports N2 SM info from SMF.

N3 GTP-U

gNB↔UPF tunnel. AMF never sees user IP payload.

Slicing & SBA

S-NSSAI selects slice. AMF often common across slices; SMF/UPF may be slice-specific. NRF discovers NFs; SCP (Rel-16) can proxy SBI; SEPP protects inter-PLMN N32.
